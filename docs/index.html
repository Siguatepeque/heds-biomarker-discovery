Research notes · hypermobile Ehlers-Danlos syndrome

We built a robot to read hEDS research papers. Here is what happened.

Hypermobile Ehlers-Danlos Syndrome does not have a lab test. It is diagnosed by checklist, and it has been that way for a long time. This page walks through an attempt to do something different: point a program at the entire research literature and let it notice connections nobody has written down yet. It covers the idea behind it, how it actually works, what it found, and a retrospective test of whether any of it is real. Including the parts where it was not, at first.

The problem, in plain terms

hEDS is the one Ehlers-Danlos subtype nobody has a lab test for. You get diagnosed by checklist: how far your joints bend on the Beighton scale, which of a long list of other symptoms you have, whether it runs in your family, and whether a doctor has ruled out everything else it could be instead. That is the 2017 international diagnostic standard, and it is still the standard today.

Real genetic leads have started showing up in just the last couple of years. We will get to those. But as of right now, nothing has turned into an actual test.

The idea

We did not want to build the obvious thing: a classifier trained on symptom checklists, which just re-learns the diagnostic criteria and calls it a "biomarker." Instead we went after something nobody seems to have tried for this disease. It is called literature-based discovery, and it is an old idea.

In the 1980s, a researcher named Don Swanson noticed something odd while reading two completely separate piles of medical papers. One pile, about Raynaud's disease, kept mentioning blood viscosity. The other pile, about fish oil, kept mentioning the exact same thing. Nobody had ever written a paper connecting fish oil to Raynaud's directly. But the pattern was sitting right there, split across two literatures that never cited each other. Swanson published the connection as a hypothesis. Years later, clinical trials confirmed it.

That is the whole idea, generalized. If a disease A is linked to some concept B in the literature, and B is linked to a gene C in a totally different set of papers, but nobody has ever written a paper connecting A to C directly, then C is worth a look. It costs nothing to check. All of this runs on free, public data. No lab access required, no patient data touched at any point.

How the robot actually works

Four steps, each one a small Python script, chained together by a single command.

1. Fetch

Pulls hEDS and HSD specific papers from PubMed. We deliberately left out bare "Ehlers-Danlos syndrome" and other subtype terms, so genes belonging to classical or vascular EDS do not sneak into the corpus. Each abstract's genes, diseases, and chemicals get tagged automatically by NCBI's PubTator3 service, so we did not have to write our own entity recognizer.

2. Graph

Turns all of that into a co-occurrence graph. Two concepts get an edge if they show up in the same abstract, weighted by how often, plus a score for how surprising that co-occurrence actually is.

3. Discover

The actual Swanson-style step. Anything directly co-mentioned with hEDS in the same abstract is filed as "already studied" and set aside. What is left, genes reachable only through a shared bridge concept and never directly, gets ranked by a common-neighbors score that discounts generic bridge terms (things like "pain," which connect to almost everything in a medical corpus) more than specific ones. This distinction turned out to matter a great deal, and it is the exact thing that went wrong twice during development. More on that below.

4. Validate

Before anything makes the final list, it gets checked against three independent public sources: STRING, to see if it physically interacts with a known hEDS-relevant protein. GTEx, to see if it is actually expressed in connective tissue. ClinVar, to see if it has any documented human variant record at all.

The real test

This pipeline's whole output is a shortlist: a claim about the future that says these genes are worth a second look (the current one is in What we found, below). The only honest way to test a claim like that is to go back in time and see if it would have held up. So we built a second script, backtest.py, that reruns the exact same pipeline using only literature published before a chosen cutoff year, and checks whether genes that real 2024 to 2025 hEDS genetics later confirmed were already showing up as candidates before that confirmation existed.

Using only papers published through 2021, more than three and a half years before the first hEDS GWAS meta-analysis went up on medRxiv in September 2025, the pipeline flags SLC39A13 as a candidate through a purely indirect literature path. In September 2025, an independent GWAS meta-analysis of about 1,800 cases and 5,000 controls, a completely different method entirely, genotyping, not literature, found genome-wide significant signal at that exact gene.

We did not trust that number the first time we saw it, and we do not think anyone should trust a result like this without trying to break it first.

Round one

An unrelated exploratory run, loosening the co-occurrence threshold just to see what a noisier pass surfaces, turned up KLK15, another 2024 hEDS gene, as a weak signal. Tracing it back led to an actual paper: "KLK15 alters connective tissues in hypermobile Ehlers-Danlos syndrome," published in iScience in August 2025, which explicitly studies KLK15 in hEDS by name. Our seed detection had been matching against the graph's single stored display name for each entity, and PubTator had normalized this paper's very specific "hypermobile Ehlers-Danlos syndrome" mention down to the generic Ehlers-Danlos syndrome ID shared by every subtype, so the match never fired. We fixed it by scanning each document's own raw text directly instead of trusting one stored name per concept.

Round two

Re-running the SLC39A13 backtest after that fix, it initially showed as "already directly studied" by 2022, which would have meant no prediction case at all. Digging into why turned up two more bugs in our own pattern list. One pattern, meant to catch the pre-2017 name for hEDS, was a naive substring match that also fired on "Ehlers-Danlos syndrome, spondylodysplastic form type 3," a completely different subtype, the exact one SLC39A13 is already known to cause. Separately, we had included "generalized joint hypermobility" as a seed term, but it turns out to be a clinical sign, not a diagnosis. We found a real paper studying it as a population explicitly distinct from EDS. We fixed both and added tests so neither can quietly come back.

Only after those two rounds of fixes did we trust the result enough to publish it. No document before 2022 co-mentions an hEDS seed term and SLC39A13 in the same abstract. Neither of the two papers that discuss SLC39A13 at all, from 2020 and 2021, is itself a seed document. The connection runs through several independently weak literature bridges, most substantially a shared "juvenile connective tissue diseases" concept appearing in 54 real hEDS papers. We hand-verified the score's arithmetic against the raw graph, not just the code path.

One more honest thing, checked while writing this. SLC39A13 is still classified as a candidate today, not yet "already studied," even eleven months after the GWAS. Exactly one document in the whole corpus directly co-mentions hEDS and SLC39A13: the GWAS preprint itself. No second paper has echoed the connection yet, so it has not cleared this method's own two-paper bar for "established." That is not a weakness in the method. It is a real, separate observation: the literature index can lag a genuine discovery by the better part of a year even after publication, which is exactly the kind of gap a tool like this is built to notice.

Worth being precise about the boundary here too. SLC39A13 was not a total unknown going in. It is the established cause of a different, rare EDS subtype, which is exactly why it had some indirect literature trail to follow. ACKR3, the GWAS's other major locus, has no connective-tissue literature footprint at all, at any cutoff we tested including today, and the pipeline correctly has nothing to say about it. KLK15 has exactly one paper with a matched disease mention in the entire corpus, and one paper is not enough independent evidence. This method gets ahead of the field when a candidate has some textual trail, however thin. It has nothing to offer for a genuinely de novo finding with no trace at all, and it is honest about the difference.

That is the proof the method has a track record. Here is what it says about right now.

What we found

With that track record established: on the corpus we had while writing this (1,301 abstracts, 1,345 entities, 20,238 co-occurrence edges), the pipeline correctly filed 24 genes as "already studied," including COL3A1, COL6A3, SMAD3, and TNXB, and surfaced 10 candidates.

Topping the list is PLOD1, which defines kyphoscoliotic EDS. Most of the rest, AEBP1, DSE, B4GALT7, and FKBP14, are similarly genes that define other EDS-spectrum disorders. That is a reasonable "maybe this whole gene family matters here too" hypothesis, not individually shocking.

Three entries deserve individual attention, for different reasons.

C1R (complement C1r) independently lines up with a 2025 to 2026 proteomics paper that found complement-cascade proteins showing up differently in hEDS patients' blood. We did not point the pipeline at it. It came out of the graph structure on its own, and it happens to match a completely separate wet-lab finding.

VWF (von Willebrand factor) reaches the list through a real, coherent bridge concept, a symptom term meaning "bleedings" that shows up in 18 real hEDS papers. Bleeding and bruising tendency is a documented hEDS comorbidity, and VWF is the gene behind a bleeding disorder. It has not been studied in hEDS by name yet, but the shape of the evidence is the same as SLC39A13 before anyone confirmed it.

BCL2A1, on the other hand, is probably noise, and we are saying so plainly rather than hiding it. Its connective-tissue expression is negligible, it is reached only through a chain of classical (not hypermobile) EDS papers, and there is no obvious biological reason to expect it. We left it in the output because hiding a weak result is worse than showing one clearly labeled as weak.

What is new here

Before writing any code, we checked whether this had already been done. As far as we could find, nobody has pointed literature-based discovery or knowledge-graph mining at hEDS before. Not even at neighboring diseases with a similar "diagnosis of exclusion" problem, like long COVID or fibromyalgia. This angle, at least, seems to be new.

What backs this up

We did not want to build this in a vacuum, so before writing any code we spent a while figuring out what had already been tried. It turns out 2024 to 2025 was a genuinely big couple of years for hEDS genetics, and the reference gene sets built into the validation step come from that work, not from other EDS subtypes' better known genes.

KLK gene family, especially KLK15
A recurrent variant turned up in whole exome sequencing of 200 hEDS patients, and it reproduces connective tissue defects when reintroduced in mice.
Norris Lab, iScience 2025
ACKR3 and SLC39A13
The first hEDS GWAS meta-analysis, pointing toward a neuroimmune and stromal story rather than a single collagen gene.
Petrucci-Nelson et al., medRxiv 2025
MIA3
Another 2024 to 2025 candidate gene, still unresolved.
TNXB, partial deficiency
The oldest lead in this space, though it only explains about one percent of cases, and serum tenascin-X testing failed as a screening tool when people actually tried it. Kept in our reference set as a weak legacy check.
A plasma ECM-fragmentation signature
Fibronectin, collagen-I, and tenascin fragments. Probably the closest thing to an actual proposed biomarker that exists right now, still unvalidated.
Ritelli et al.
The HEDGE Study
The Ehlers-Danlos Society's own large scale sequencing effort, covering 1,000 patients, still producing results.

What we did not do, and why

Three things worth naming, and why each one was skipped

Clustering patients into subtypes by symptoms

Already done, and done well. Mayo Clinic ran K-means and UMAP on more than 2,100 real patients and published real subtypes. We do not have that kind of data, and running the same analysis on something worse would not add anything.

Wearables and video-based biomarkers

Genuinely exciting research: AI-scored hypermobility from video, wearable heart-rate-variability tracking. Every dataset behind it is available on request only, not public. That confirmed literature mining was the right lane for a project built entirely on public data.

Swapping in SemMedDB instead of raw co-occurrence

SemMedDB gives semantic relationships instead of "these two things appeared near each other," which sounds strictly better. It was deprecated in December 2024 and has not been updated since, so it would miss both the 2025 GWAS paper and the 2024 KLK15 finding above, and it needs a UMLS license to even access. Not worth the tradeoff for something meant to stay current and easy to run.

Hey, please check this

We would rather tell you exactly what to be skeptical of than let you find it yourself.

  • ✎ VWF and C1R are today's live candidates, and they deserve harder scrutiny than a single pass. Both reach the list the way SLC39A13 did before its GWAS confirmation, through indirect evidence, not direct study. VWF's bridge concept looks real but has not gone through the two rounds of adversarial re-checking that SLC39A13's result did. C1R's match to a 2025-26 proteomics finding is suggestive, not independently re-verified here. Run the backtest and the graph queries yourself before treating either as more than a lead.
  • ✎ BCL2A1 is flagged weak on purpose. We left it in the shortlist instead of quietly dropping it. Read it as the pipeline's noise floor, not as a finding.
  • ✎ The seed-matching patterns are a hand-built list. We found and fixed two false positives in that exact list while building this project. There could be a third we have not found. If you extend the search scope, check any new pattern against a real, messy abstract before trusting the output.
  • ✎ The "already studied" bucket depends on PubTator3's tagging being right. It mostly is, but automated tagging makes mistakes, and we have not manually audited every one of the 24 genes in that bucket.
  • ✎ Run the tests before trusting a change. They cover the exact logic that has actually broken before. If you touch the discovery step, run them first.

What this is not

This is a hypothesis-generating research tool, not a diagnostic instrument. There is no confirmed diagnostic biomarker for hEDS in the published literature. Not from this project, not from anyone, not yet. Nothing here should be used to include, exclude, or otherwise influence an actual diagnosis. At best, a candidate on this list is a starting point for someone with a lab to look closer.

Try it yourself

Everything here runs on free, public APIs. No account, no key, no patient data. 

python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt

python pipeline.py --top-n 20
python backtest.py --cutoffs 2019 2020 2021 2022 2023 2024 2025 2026

Most of the runtime is just being polite to free APIs, about one request per second, not actual computation. The full source, the tests, the raw results, and the exact evidence trail behind the retrospective test are all in the repository.
